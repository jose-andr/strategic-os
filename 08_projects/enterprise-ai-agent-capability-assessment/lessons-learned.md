# Enterprise AI Agent Capability Assessment — Lessons Learned

## Purpose

Capture reusable lessons from the initial enterprise AI capability assessment.

These lessons should only move into the wider Strategic OS lessons library if repeated use confirms them beyond this project.

## Lessons

### L001 — Use enterprise AI closest to the authoritative source

**Status:** Validated in this assessment

**Lesson:**  
The most useful enterprise agent is often the one already embedded in or connected to the organisational system that owns the information.

**Examples:**

- CoMpanion for internal organisational processes and guidance;
- Teams Copilot for Teams activity;
- Genie for governed analytical evidence.

**Implication:**  
Prefer native organisational capability before creating cross-platform agents or duplicate knowledge stores.

### L002 — Provenance matters more than eloquence for organisational guidance

**Status:** Validated in this assessment

**Lesson:**  
For policies, procedures and internal process questions, the ability to identify the organisational source, form or knowledge article is more valuable than a polished generated answer.

**Implication:**  
Judge organisational knowledge agents on source visibility and navigation value.

### L003 — Guidance can create useful automation value without execution

**Status:** Validated in this assessment

**Lesson:**  
An enterprise agent does not need write access to save meaningful time.

CoMpanion reduces administrative effort by finding the correct process, form and pathway even though the user still completes the action.

**Implication:**  
Measure administration removed rather than autonomy achieved.

### L004 — Do not build a custom agent when a native capability already covers the need

**Status:** Validated in this assessment

**Lesson:**  
A custom agent introduces instructions, permissions, configuration and maintenance.

It should only exist when an evidenced recurring gap cannot be handled by an existing approved capability.

**Implication:**  
The proposed custom Meeting Admin agent was rejected because native Teams Copilot should be used first.

### L005 — Enterprise AI roles should remain narrow

**Status:** Validated in this assessment

**Lesson:**  
Clear role boundaries reduce duplication and confusion.

Current useful boundaries are:

- CoMpanion → internal organisational navigation;
- Teams Copilot → Teams activity;
- Genie → analytics;
- Strategic OS → interpretation and reusable knowledge.

**Implication:**  
Do not force every enterprise AI platform to perform every type of work.

### L006 — Test AI through real workflows, not product catalogues

**Status:** Validated in this assessment

**Lesson:**  
Feature availability does not prove that a capability is licensed, enabled, permissioned or useful in the organisational environment.

**Implication:**  
Future Rovo and Miro AI assessment should happen inside actual project workflows rather than through generic feature exploration.

### L007 — Low-maintenance partial automation can be preferable to complex full automation

**Status:** Emerging

**Lesson:**  
A workflow that automatically prepares most of the work but retains one simple human step may be better than adding an agent, connector or workflow solely to remove that final step.

**Example:**  
Teams transcription currently requires meeting-level configuration, but this alone does not justify building a custom automation layer.

**Implication:**  
Apply the Strategic OS architecture rule:

> Prefer complex-once, simple-to-run — but do not introduce complexity unless the recurring burden is material.

### L008 — Creativity and design should not be delegated merely because enterprise AI exposes the capability

**Status:** Confirmed operating choice

**Lesson:**  
Enterprise AI is most valuable here as a retrieval, evidence and administrative support layer.

Strategic judgement, creativity, service design and visual communication remain human-led.

**Implication:**  
Do not evaluate enterprise agents on capabilities that do not improve the intended operating model.

## Review rule

Only promote these lessons into wider Strategic OS reusable knowledge when repeated project use confirms they remain useful outside this assessment.
