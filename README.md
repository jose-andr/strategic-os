# Strategic OS

## Purpose

Strategic OS is a personal augmentation system designed to help transform complexity into strategic decisions, improve stakeholder alignment, and create more strategic opportunities.

The system supports a Business Design and Human-Centred Design practice through AI-enabled sensemaking, decision support, stakeholder management, analytical interpretation, operating discipline and career development.

## North Star

> Increase strategic opportunities by helping leaders make better strategic decisions.

## Desired Reputation

> "He helps us make better strategic decisions."

## Strategic Positioning

A customer-centred strategic advisor who connects:

- Customer outcomes
- Organisational outcomes
- Evidence and insights
- Systems thinking
- Service and business design
- AI-enabled ways of working

## Why This Exists

My strongest value is not producing artefacts.

My value comes from:

- Framing the right problem
- Making sense of complexity
- Connecting customer and organisational outcomes
- Developing practical recommendations
- Supporting strategic decision-making
- Helping people align around useful action

This system exists to amplify those strengths while reducing common constraints such as:

- Perfectionism
- Over-analysis
- Starting too many initiatives
- Delayed stakeholder engagement
- Difficulty translating insights into organisational action
- Losing reusable learning across projects, conversations and decisions

## Design Principles

### Decision First

Outputs should be structured around decisions rather than findings.

### Human In The Loop

Humans make decisions.

Agents provide synthesis, recommendations, prompts, analysis, coordination and coaching.

### Privacy By Design

No organisational source data is stored in this repository.

Only personal knowledge, frameworks, observations, caveats, summaries and reusable patterns are retained.

### Employer Independent

Knowledge should remain portable and useful throughout a career.

### Markdown First

All strategic knowledge should be AI-readable, portable and future-proof.

Markdown remains the durable content format regardless of which workspace or interface is used.

### Ship Over Perfect

Progress, learning and influence are prioritised over unnecessary refinement.

### Evidence With Caveats

Evidence, assumptions, interpretation, recommendation and action should remain distinct.

Analytical outputs should state their source, caveats, confidence and human review requirements.

### Low Management Overhead

Prefer systems, applications and architecture that require minimal ongoing human administration once configured.

Complex initial setup is acceptable when it creates a stable, low-maintenance operating model.

Prefer complex-once, simple-to-run over simple-to-start, manually-maintained forever.

### Strategic OS

Strategic OS uses a cloud-first layered architecture:

- **Slack** as the primary conversational interface with Strategic OS agents
- **Agents** for reasoning, synthesis, challenge, coordination and decision support
- **GitHub web** as the primary cloud-accessible Strategic OS workspace
- **GitHub repository** as the authoritative, version-controlled source of truth for Strategic OS
- **Strategic OS Markdown files** as durable, portable knowledge
- **Obsidian desktop and mobile** as optional enhanced Markdown workspaces for navigation, linking, reflection and visual thinking when available
- **Relevance AI** for agent memory and reasoning where appropriate
- **Make.com** for workflow orchestration where appropriate
- **Microsoft 365 Copilot** as an enterprise AI layer for authorised organisational knowledge, meetings, communications and approved workflow automation where enabled
- **PLAUD** as an optional conversation-capture capability to evaluate only where organisational approval, consent, privacy, security and records requirements permit

The operating distinction is:

> Slack is where the user primarily interacts with Strategic OS agents.  
> GitHub web provides the primary cloud-accessible Strategic OS workspace.  
> GitHub is the authoritative repository and source of truth for Strategic OS.  
> Obsidian provides an optional enhanced interface over Strategic OS Markdown on supported desktop and mobile devices.  
> Microsoft 365 Copilot works inside the approved organisational environment with authorised organisational knowledge and workflows.  
> Organisational systems remain systems of record.

Strategic OS must remain fully usable without Obsidian.

Obsidian must not become a separate divergent copy of Strategic OS. Where Obsidian is used, it should work over the repository Markdown or through a controlled synchronisation approach that preserves GitHub authority.

Strategic OS stores interpretation, not raw organisational data.

## Source Of Truth Rules

Strategic OS does not replace systems of record.

| Information Type | Source Of Truth | Strategic OS Role |
|---|---|---|
| Strategic OS structure and durable knowledge | GitHub repository | Authoritative repository for frameworks, templates, agent guidance and reusable knowledge |
| Strategic OS cloud workspace | GitHub web | Primary browser-accessible workspace for reading, reviewing and maintaining Strategic OS |
| Optional enhanced Strategic OS workspace | GitHub-backed Markdown viewed through Obsidian desktop or mobile | Navigate, author, link, reflect and visually explore without changing source-of-truth ownership |
| Governed data | Databricks or approved data platform | Store interpretation, caveats and decision-support evidence only |
| Reporting | Power BI or approved reporting layer | Store source rules and caveats, not copied reports |
| Organisational documents | SharePoint or OneDrive | Store summaries or reusable patterns only |
| Enterprise AI | Microsoft 365 Copilot where approved | Support authorised organisational synthesis, search and automation without changing source ownership |
| Communication | Teams, email, calendar and approved collaboration tools | Store abstracted follow-up or decision context only |
| Delivery tasks | Jira or official task system | Store summaries and coordination notes only |
| Customer records | Official customer systems | Do not store records in Strategic OS |
| External meeting capture | Approved capture service only | Retain only reviewed, privacy-safe abstraction where permitted |

The next operating step is to use the cloud-first architecture in real work while preserving source-of-truth, privacy and human-review rules.

Test the system on real work:

- capture one current item in `00_inbox/`
- interact with the relevant agent through Slack or another approved interaction surface
- use GitHub web as the primary cloud-accessible Strategic OS workspace
- use the relevant template
- review the output
- store approved durable knowledge in the correct GitHub repository folder
- optionally use Obsidian desktop or mobile to navigate, link, reflect on and visually explore repository knowledge when available
- use Microsoft 365 Copilot for authorised organisational knowledge, meeting and administrative support where enabled
- evaluate PLAUD only where organisational approval and governance permit
- convert useful work into a decision, opportunity, lesson, stakeholder pattern, project artefact or career evidence

No further framework expansion is recommended unless repeated real use exposes a genuine gap.
